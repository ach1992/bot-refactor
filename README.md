# AChBot

A Persian-language PHP Telegram bot for VPN subscriptions, wallets, payments,
Native account management, staff operations and support. Wallet-first uses one
financial ledger, one funded service engine and independent delivery. PasarGuard
is the shipped Native adapter; additional providers and payment methods use the
same registered extension boundaries.

[Latest published release](https://github.com/ach1992/bot-refactor/releases/latest) · [Releases](https://github.com/ach1992/bot-refactor/releases) · [Issues](https://github.com/ach1992/bot-refactor/issues)

**This README describes Wallet-first source.** A published or installed older
release has its own tag-matched documentation. Release publication is not
installation or activation.

## Requirements

- Linux, HTTPS, PHP web/CLI with mysqli/mysqlnd, curl, zip and gd (source CI: PHP 8.5).
- MariaDB and a dedicated database/account per bot.
- Telegram bot token, Owner numeric ID, private per-instance webhook secret.
- Authorized PasarGuard API and configured native subscription URL.
- One per-bot Cron coordinator, Linux /proc, PHP CLI posix_geteuid, flock,
  proc_open and a trusted private lock directory.

## Install

1. Obtain a published Wallet-first runtime ZIP, manifest, SHA256SUMS and exact
   tag-matched private setup source. Verify them before extraction. GitHub's
   autogenerated source archive is not a runtime installer.
2. For a new bot, follow [fresh installation](docs/post-v9/FRESH-INSTALL.md)
   and import only the matching `database/current-schema.sql` into a new
   empty database. Keep private config, SQL and setup tools outside served paths.
3. Configure the private `baseInfo.php`, authenticated HTTPS webhook and the
   one-minute `settings/cronRunner.php` per the installation guide.
4. Run [installed identity diagnostics](docs/post-v9/INSTALL-DIAGNOSTICS.md)
   and [read-only readiness checks](docs/post-v9/PAYMENT-READINESS-PREFLIGHT.md).
   Source checks do not prove live customer, merchant or Native acceptance.

**Existing bots:** this is not an in-place upgrade. Use the separately approved
[manual transfer and reconciliation contract](docs/post-v9/WALLET-FIRST-ARCHITECTURE.md#cutover-decision--controlled-manual-database-transfer-owner-2026-11-24).
Preserve actual balances, identities, credentials, entitlements and original
evidence. Never apply construction SQL to an existing database, replay
historical pending workflows or overwrite a live bot merely because a ZIP exists.

## Development and delivery

Use the current PHP 8.5 validation gate and independent review when required.
Build from a clean committed checkout using `tools/package_current.py`
(see the CI guide). Runtime membership and checksums come from the selected
commit, not a fixed historical inventory. Do not commit credentials, private
configuration, customer records, logs or generated release files.

Active release and installed-acceptance work lives in [GitHub Issues](https://github.com/ach1992/bot-refactor/issues).
Use the [release history](https://github.com/ach1992/bot-refactor/releases) for
published versions and the [pre-cleanup reviewed documentation](https://github.com/ach1992/bot-refactor/tree/c43d671a1f50c582930d15db0c094bdf20ff4f19/docs)
for historical implementation evidence; these are not current setup instructions.
