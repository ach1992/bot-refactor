# AChBot V6.1 backup acceptance

- `python3 tools/backup_hotfix_contract.py`: compare pinned merged V6 Git blobs against every original runtime member, allowing only the backup body in `config.php`, the backup scheduling block in `settings/rewardReport.php`, and one new guarded `src/Backup/Database.php`. Original 51 other members remain byte-identical.
- `python3 tools/test_backup_hotfix.py --native-zip`: PHP process synthetic cases (currently 26): valid MariaDB- and MySQL-shaped fixture dumps/ZIP/Telegram simulation (including a stream crossing the 64-KiB scan boundary), failed Telegram, dump nonzero, empty dump, **exit-zero >1000-byte junk dump**, **exit-zero truncated dump missing completion marker**, missing SQL header, missing schema/table DDL, trailing junk after the completion footer, missing binary, missing recipient, missing extension, ZIP failure, due/not-due/missing timestamp, failed schedule with no DB timestamp update and bounded cooldown, and locked invocation. SQL validation requires a genuine MySQL/MariaDB dump header, schema DDL and the final dump-completion marker, scanned in bounded memory. It is a structural gate and **not** full SQL parsing or restore proof. A schedule.invalid_large case executes real send() under the scheduling logic and checks zero Telegram sends/zero timestamp writes. Two deliberate negative mutation controls must detect bypassed Telegram or invalid-SQL checks. A **real two-process PHP** flock contention test ensures no duplicate sends/writes during lock ownership and confirms a later eligible run succeeds. On the dedicated local test server without PHP zip, omit `--native-zip` to use a test-only ZIP adapter; CI requires native `ZipArchive` for successful cases.
- Real MariaDB 10.11 regression: stock `mysqldump` may end a complete, successful SQL dump with a **space-padded single-digit hour**, e.g. `-- Dump completed on 2026-10-13  4:31:51`. V6.1 RC1 incorrectly required two hour digits and rejected this valid marker as `dump_invalid_or_incomplete`. The fixture reproduces the original failure first, then proves `send.mariadb_space_hour`, `send.mariadb_space_zero` and `send.mariadb_space_nine` succeed; malformed hour 24 and minute 61 still fail. No SQL/ZIP/Telegram privacy or success-gating checks are bypassed. The RC2 source hotfix was independently reviewed and merged, and the owner reports installing it on the affected bot with successful Telegram ZIP receipt. This is **not proof of successful restore**; that test was explicitly declined.
- `python3 tools/test_backup_hotfix_native.py`: existing owned socket-only ephemeral MariaDB with unchanged original 23-table schema and synthetic rows; dedicated synthetic MySQL login with complex password through mode-0600 option file; **real** `/usr/bin/mysqldump` produces a usable real ZIP; simulated delivery only. No production DB/service or real Telegram.
- `python3 tools/test_backup_hotfix_http.py`: local loopback PHP GET of direct new module must return 404.
- `python3 tools/check_backup_hotfix.py --focused`: targeted development tests and 53 PHP lints, not release acceptance.
- `python3 tools/check_backup_hotfix.py --report /tmp/achbot-backup-full.json`: full exact-candidate gate: all new tests using native ZipArchive, plus unchanged V6's frozen V0–V6 full original-schema/native acceptance executed **from immutable merged V6 Git archive** to avoid rewriting golden expectations. Run only in a disposable environment with MariaDB tooling and PHP zip installed.
- `python3 tools/package_backup_hotfix.py --output /tmp/achbot-backup-candidate.zip` and `python3 tools/verify_backup_hotfix_package.py --zip /tmp/achbot-backup-candidate.zip --manifest /tmp/achbot-backup-candidate.zip.manifest.json`: 54 source-only runtime members, exact clean committed HEAD/tree, SHA256 and Git blob identity. No secrets, backups, customer files or DDL data in the archive.

CI: PHP 8.1 compatibility matches the observed aaPanel runtime; PHP 8.4 runs full pinned historical + candidate gates. RC2 exact-candidate and post-merge CI both succeeded (see [PR #20](https://github.com/ach1992/bot-refactor/pull/20) and [post-merge CI](https://github.com/ach1992/bot-refactor/actions/runs/38330706668)). Owner-observed Telegram ZIP delivery is recorded in Issue #18; **SQL restoration is NOT TESTED at owner request**. On future changes to dump-format parsing, include a deterministic pre-fix rejection and post-fix acceptance of real MariaDB output such as a space-padded single-digit hour, plus negative malformed-time and incomplete dump cases. Never replace native-client fixture variety with one idealized timestamp or claim a successful channel upload proves restorability.
