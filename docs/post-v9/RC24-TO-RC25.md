## Changes relative to RC24

1. Logical Panel Group is an administrator-owned declaration for both Marzban and PasarGuard. The admin can assign, change or clear a valid Panel Group even when orders, plans, payments or unfinished journals exist. Different URLs, credentials or provider-connection records do not block assignment when the administrator knows the logical entries use one physical panel. The assignment modifies ONLY server_info.panel_group_id; it never changes accounts, orders, plans, payments, customer access or remote Native state. Provider and Group validation and administrative authorization remain in force.
2. Native account/finance identity checks still apply at consumption. New Marzban plan intents pin the original Native username and Panel Group in the existing intent JSON. The import/plan/transfer guards also inspect historical server/order identity, preventing unresolved journal bypass by deleting an old local order and reassigning Group A to B. Legacy unresolved journals missing the new Native username are conservatively held for the recorded server/current Group until operator reconciliation. Committed journals and unrelated known subscriptions remain usable.
3. Administrator Group messages are provider-neutral. The real bot.php callback has deterministic MariaDB injected-write-failure rollback and retry coverage for both providers.
4. Native CREATE concurrency acceptance now confirms independent record locking plus specific SQL wait, rather than relying on an intermittently missing InnoDB metadata view.

The administrator is responsible for declaring true physical-panel membership. Shared Group membership by itself never proves Native account identity or authorizes a Native mutation.

## SQL / compatibility
